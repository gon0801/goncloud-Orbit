# AC10 — como se probo el aislamiento

Criterio: cambiar solo la estimacion, con la misma solicitud comercial y la
misma economia observada, deja identicos el plan, la huella, el payload de
alta, el target, budgets, bids, la elegibilidad y la recuperacion v1/v2.

## Que cubre el test

Archivo: `tests/test_estimacion_aislamiento_fabrica.py`.

El test parchea `app.fabrica_web.adjuntar_estimaciones` y devuelve dos sobres
S5 distintos (`disponible` con contribucion `42.5000` / `36.6379` vs
`incompleta` con principales null). La solicitud POST y los datos de
`v_margen_producto` no cambian.

Luego afirma:

- `POST /api/fabrica/plan` v1 y v2: JSON sin marcas de tiempo incidentales
  igual, huella igual, `parametros` y objetivo/target iguales.
- El cuerpo del plan no contiene la clave `estimacion` a ninguna profundidad.
- `pasos_del_rol` produce el mismo payload Amazon (campaña, ad group, ads,
  semillas). `_mutar` sigue simulado. No hay POST real a Ads.
- GET catalogo y evaluacion SI muestran los dos sobres distintos.
- `elegible` / `seleccionable` no cambian.
- `margen_neto_pct` observado permanece `40.00000000000000000` y no se
  sustituye por `contribucion_pct`.
- GET lote v1 y reconciliar v2 no cambian al cambiar el sobre.

Candado estatico: `app/optimizer/**`, `app/ads/write.py` y `app/fabrica_plan.py`
no importan ni mencionan `estimacion_proyeccion`, `estimacion_repository` ni
`estimacion_venta`.
